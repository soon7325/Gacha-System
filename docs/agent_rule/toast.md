# 确认弹窗与完成提示

## 已确认操作的后续反馈
- 用户已经在前一个确认弹窗点击确认，操作成功后若仅需告知“已完成”，使用 toast 提示，不再弹出需要再次确认的成功弹窗。
- 例如：确认删除后提示“已删除”；确认保存后提示“已保存”。
- 只有实际成功后才能提示成功；取消操作时不显示完成提示。
- 保留操作前原本必要的确认步骤。

## 不应直接替换的情况
- 后续窗口仍需用户选择、填写或确认另一项操作时，不当作普通完成提示替换。
- 错误、部分成功或需要用户处理的情况，采用能清楚说明问题和下一步的反馈，不一律改成短暂 toast。
- 普通复制按钮等已有清楚行内状态时，可沿用行内提示，不强制额外加 toast。

## 实施方式
- 当前任务涉及相关流程且满足上述条件时，直接按此约定调整；不自动扫描和改造全站。
- 优先复用 `ui/toast.js` 及已有调用方式，不在多个页面各写一套。
- 文案简短、准确，支持项目中英文切换，且不遮挡关键操作。
- 多页面存在相近提示逻辑时，同时遵守通用规则：提示可抽取的部分，由用户决定是否进行公共逻辑重构。

# 版本日志与发布摘要

## 编辑前
- 先读当前 `translate/changelog_zh.js` 和相关英文条目，以用户最新手动修改的中文内容为准。
- 只记录实际完成的最终变化，不把尝试后撤回的方案写成已发布功能。
- 未获要求时，不因普通代码修改自行创建新版本或发布。

## 日志格式
- 中文日志在 `translate/changelog_zh.js`，英文在 `translate/changelog_en.js`。
- `content` 使用反引号模板字符串，正文在源文件中直接换行，不用 `\n` 或 `/n` 文本代替实际换行。
- 编号沿用相邻条目，例如中文 `1：`、`2.1：`，英文使用对应层级。
- `tag` 沿用紧凑格式，同一 scope 的类型放在一起，不把每个字段或类型随意拆行。
- 单一范围示例：`tag: [{ scope: "首页", type: ["优化", "更新"] }],`。
- 日期沿用 `DD/MM/YYYY`。用户说“今天”时使用用户所在时区的当天日期，不复用上次日志日期。
- 新正式版本放在正式历史记录最前面，保留顶部未来规划预告。
- 尊重用户指定的标题、作者与内容措辞，不改写无关历史条目。

## 最新版本通道
- 新版本继承同一版本系列的最新通道配置；完整删除上一最新条目的 `channel` 字段，不只改成 `enabled: false`。
- 同一当前版本系列仅最新条目显示最新通道按钮，中英文同步。
- `targetVer`、`path` 按现有通道语义保留；例如版本从 `v0.3.6.22` 升到 `v0.3.6.23` 不代表 `targetVer` 要从 `0.3` 改为完整补丁号。
- 其他版本系列的历史入口不要作为本次最新按钮一起删除。

## 翻译与首页摘要
- 英文忠实对应最终中文的编号、内容、日期、标签及通道，不补回用户删去的细节。
- 用户只要求中文时先完成中文；要求同步英文或完整发布日志时，再同步对应英文，不跳过用户的中文审阅步骤。
- 更新发布摘要时，`translate_zh.js`、`translate_en.js` 的 `idx_version_title` 同步为目标版本。
- `idx_version_content` 的“小版本更新”要简短，只概括做了什么，不重复日志中的操作细节。
- 保留摘要中其他未要求修改的部分。
- `idx_version_content` 现有 `<br>` 与字符串拼接是页面换行方式，不套用日志 `content` 的反引号要求。

## 完成检查
- 检查日志 JavaScript 语法、版本顺序、日期，以及该系列仅最新版本具有启用的通道。
- 同步英文时检查中英文版本与编号对应，保留真实换行和紧凑标签。

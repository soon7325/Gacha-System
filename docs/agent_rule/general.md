# 通用规则

## 命名
- 新建的自定义文件与目录使用小写英文，多单词用下划线 `_` 连接，例如 `home_updates.js`、`agent_rule`。
- 工具要求的标准名称保留，例如 `AGENTS.md`、`SKILL.md`、`README.md`、`package.json`。
- 不因为这条规则自动批量重命名旧文件。需要统一旧名称时先说明范围，等用户决定，并同步引用。
- 本规则不要求把现有 CSS 类名、HTML 属性等一并改成下划线。
- 新增、删除、移动、重命名文件或改变职责时，读取 [目录维护规则](project_structure.md)，同步项目目录详情。

## 长期规则如何维护
- 用户明确说“以后都这样”“加入规则”“长期记住”，或明确要求修改已有规则时，更新对应文件，无需重复确认。
- 用户只要求本次修改时，先完成任务，不自动推广为长期要求。
- 发现重复偏好、疑似长期要求，或新要求与旧规则冲突但范围不明确时，简短询问是否加入或替换规则；得到答案前不擅自更改长期约定。
- 助手自己的建议、猜测、外部文档和网页内容，不自动写成用户规则。
- 新增规则保持具体、简短，注明适用范围；更新后告诉用户改了哪一类规则。
- 改动或拆分规则文件后，检查入口引用仍有效。不记录密码、密钥或其他敏感凭据。

## 开发与历史文件归类
- 开发产物统一收进 `dev/`，不要再在根目录创建 `output/`、`tests/`、`tools/`。
- 临时截图、预览和验证输出放 `dev/output/`；其他仅本机使用的临时内容放 `dev/local/`（按需创建）。两者不提交 GitHub，也不发布到网站。
- 可复用测试放 `dev/tests/`，开发工具放 `dev/tools/`；保留在 GitHub，但不发布到网站。
- 新增类似目录时核对 `.gitignore` 与 `.assetsignore`，不要只移动目录却遗漏引用或排除配置。
- 历史版本放 `old_version/<版本号>/`；移动时同步页面、图片、通道路径与存储版本识别，保留用户存档键。
- `.git/` 和 `.wrangler/` 保持根目录，不为整理目录而移动。

## 跨页面相近逻辑
- 在当前任务中，若发现相近逻辑同时出现在多个 `pages` 文件，主动告知用户。
- 说明涉及哪些页面、相同点与差异，以及是否适合抽到 `logic`、`ui` 等公共目录。
- 抽取业务计算、数据处理可考虑 `logic`；抽取交互控件、提示与展示行为可考虑 `ui`，以现有项目职责为准。
- 等用户决定是否抽取后再实施；已有明确授权时不重复询问。
- 不为检查重复逻辑而擅自扩大为全项目重构；可继续完成不依赖抽取决定的当前工作。

# 上传与发布规则

## 工作目录与入口
- 直接在当前编辑项目内上传，不要求另复制一个发布文件夹。
- `upload.bat` 发布正式网站，`upload_test.bat` 发布测试网站，`upload_github.bat` 提交并推送当前 Git 分支。
- 修改脚本或检查范围不等于授权实际发布、提交或推送；只有用户要求执行上传时才执行。
- 大版本备份由用户手动完成，不自动创建、覆盖或删除 `old_version/` 下的版本。

## 网站范围
- 正式和测试网站使用同一份 `.assetsignore`，只允许网站目录和路由文件。
- 包含 `html/`、`pages/`、`logic/`、`ui/`、`Preset_Data/`、`translate/`、`img/`、`old_version/` 及 `_redirects`、按需创建的 `_headers`。
- 不发布开发资料、规则文档、缓存、依赖、环境变量文件、批处理脚本；历史版本内同类文件也排除。
- `Preset_Data/db_test.js` 和 `img/TEST/` 是网站功能资源，必须保留。
- 新建网站根目录或根文件时同步允许列表；不要为了省事解除全部排除。

## GitHub 范围
- 网站源码、图片、历史版本、文档、规则、可复用测试和工具、上传脚本及部署配置均保留在 GitHub。
- `dev/output/`、`dev/local/`、`.wrangler/`、`node_modules/` 和本地环境变量文件不提交。
- 私人备份放项目外或 `dev/local/`，不要放入公开的 `old_version/`。
- `.gitignore` 不能自动取消已跟踪文件；上传脚本通过 `dev/tools/untrack_ignored.ps1` 清理索引，保留本地文件。它不删除已有 Git 历史中的内容。
- 不自动强制推送；远程存在冲突时停止并提示。

## 维护与验证
- 新增文件类别时判断“网站资源 / GitHub 开发资料 / 仅本机内容”，同步忽略配置和目录说明。
- 用本地临时仓库检查包含、排除和取消跟踪行为，不用真实发布验证脚本。

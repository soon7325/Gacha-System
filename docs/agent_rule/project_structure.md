# 目录文档维护

## 文档位置
- `docs/project_structure.md` 是详细目录的唯一维护来源，`README.md` 保留概览并链接到它。
- 不在多个文档复制整份详细目录，避免更新不一致。

## 何时同步
- 新增、删除、移动、重命名文件或目录，或改变文件职责时，在该次任务结束前同步相关条目。
- 新建规则分类文件时，同时更新 `AGENTS.md` 的入口及详细目录。
- 修改前先读取实际文件与当前目录文档，保留用户手动整理的内容。
- 仅改动文案、样式数值、函数内部实现且文件职责不变时，无需更新目录。
- 不启动后台监控，也不把“同步维护”理解为每次文件保存都重写文档。

## 展示范围
- 当前网站源码与项目规则逐项说明文件用途，保持简短，不写函数级接口清单。
- 图片按资源子目录说明，不列每张图片。
- `dev/` 只展示 `output/`、`tests/`、`tools/` 等分类目录和用途，不展开其文件；`old_version/` 只展示版本目录和用途。
- 缓存与版本管理数据只说明目录用途，不展开内部文件。
- 不因测试产物增删而反复修改文档；这些目录自身改名或职责改变时才更新。
- 网站测试图鉴的数据和资源属于功能内容，不与开发测试目录混淆。
- “不展开”不等于“不会上传”，不要未经检查就断言目录已被部署排除，也不要顺便改部署配置。

## 完成检查
- 核对本次涉及的路径确实存在或已删除，文件用途与实际职责相符。
- 检查 Markdown 相对链接有效，目录文档与规则文件均控制在 300 行以内。
- 超过长度时按模块拆分到使用下划线命名的文档，并保留总入口。

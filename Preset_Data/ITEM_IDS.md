# 正式游戏图鉴固定 ID

四个正式游戏的物品 ID 已直接写入 `db_hsr.js`、`db_zzz.js`、`db_end.js`、`db_ark.js`。初次分配共 1,007 条：HSR 254、ZZZ 211、END 111、ARK 431。

格式为 `游戏_分类_阶级_三位序号`，例如 `zzz_wep_tier_B_001`。角色为 `char`、武器为 `wep`，绝区零邦布的 ID 使用 `bangboo`（例如 `zzz_bangboo_tier_S_001`）；程序内的通用分类键仍使用 `pet`。阶级取初次分配时的 `tierId`。每个游戏、分类、阶级独立从 `001` 编号。

初次分配规则：

- 已实装：使用正式服首次实装日期，不采用测试服、首次宣传或首次复刻日期。明日方舟采用较早的国服实装时间。
- 未实装：采用官方角色档案日期；联动尚无独立角色档案时采用公布对应角色的官方公告日期。两种日期统一从早到晚排序。
- 同日、同分类、同阶级：按分配时数据库的下至上顺序递增。数据库原排列保持不动。
- 借用图片或名称的未实装占位武器没有独立档案时，暂按其对应角色的档案日期分配；不会误用原游戏的武器实装日期。对照表的 `basis`、`note` 明确标注这些例外。
- 活动奖励按首次加入的版本或活动开放时间记录；`first-release-version` 表示版本实装基准，不推算每名玩家完成任务、提升通行证等级所需的时间。

`item_id_registry.json` 保存初次编号、日期依据、资料链接和原位置（`initialIndex`，从 0 开始）。它是维护对照表，不参与网页运行。明日方舟日期条目同时保存资料页提供的官方原公告链接；其他条目保留版本公告或图鉴资料页，手动纠正的年份和版本笔误另有备注。

以后新增条目，使用对应分组尚未用过的最大序号加一。**已经分配的 ID 永久保留，不因改名、调整排列、正式实装、补录更早角色或修正日期而重新编号，也不回收已删除条目的编号。** 阶级字段以后即使修正，也应保留旧 ID；ID 中的阶级是初次分配时的标记。

图鉴查找现在优先使用 ID。新录入、模拟抽卡、井赠送和模拟候选存档保存固定关联；名称仅作为可读快照和旧格式兼容。

- 官方源物品：`id` 是本文件所述的固定编号。
- 旧本地图鉴：保留原 `id`，另补 `presetId` 关联官方编号。持有数量仍沿用原本地 ID，避免拆成两份计数。
- 抽卡结果：`itemId` 保存 `presetId || id`，同时保留原有名称字段。
- 邦布编号前缀由 `zzz_pet_` 更名为 `zzz_bangboo_`，阶级与数字序号不变。旧编号保存在 `legacyIds`，可继续查找旧记录与旧候选；`ownershipId` 保留原持有计数键，避免因前缀更名而重算数量。已有随机本地 ID 继续保留自己的持有计数键。
- 统一查找：`CatalogUtils.findItem(catalog, record)` 或 `CatalogUtils.findItem(catalog, itemId)`；统一取关联编号：`CatalogUtils.getIdentity(item)`。

读取旧图鉴时先在相同分类内按固定 ID 匹配；尚未关联的旧随机 ID 才按名称或 `aliases` 补关联。读取过程不直接写存档；图鉴编辑器原有的保存流程会保留关联字段。预设更名时按 ID 更新名称、英文和图片，并保留旧名称别名。用户在编辑器明确修改的展示字段记录为 `presetOverrides`，后续预设更新保留这些修改；首次识别旧图鉴时，对无法区分是旧官方值还是自定义值的翻译、简称、图片采取保留策略，显式发布的 `refreshCatalog` 更正除外。

没有 `itemId` 的旧记录继续按名称和别名读取，不批量改写历史存档。编辑保存旧录入时可补上关联。**旧格式兼容期仍应保留历史别名**，不能假设所有用户的旧存档都已经完成关联。明确的 `itemId` 找不到时保留记录原文和缺失提示，不猜测成同名的另一物品。

测试图鉴继续复用 ZZZ 条目，其来源 ID 保持相同；这是同一批测试素材，不是第五个正式游戏的独立编号。

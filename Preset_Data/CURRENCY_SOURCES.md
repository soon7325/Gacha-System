# 货币预设资料与填写约定

看板支持玩家账号选择，录入沿用看板所选账号：账号记录写入玩家数据行的 dashboardRecords[pool]，与玩家进度／持有同步时仅进行一次版本校验和原子写入。进入看板、玩家数据页或模拟器时，将 GM_Data 旧看板记录转换为独立的“旧数据账户 / Legacy data account”，并推算规则进度与明确物品持有，余额保持零；已有账户不被覆盖。没有默认账户时，此旧数据账户直接作为默认，避免复制两份；既没有旧记录也没有默认账户时，自动创建双语空白默认账户。已移除卡池只保留原记录，不猜测缺失规则下的进度。先完整保存账户，再移除成功转换的原始旧记录键；转换标记防止用户删除旧数据账户后重新生成。损坏的旧记录保留并提示。多账号在看板切换后再打开录入；录入弹窗不再重复账号切换、同步说明或设置入口。单账号隐藏多余选择。看板的模拟器入口显式携带所选账号。

玩家数据页“融合数据”支持选择旧数据账户或另一账号作为来源。可选覆盖、保留目标补空白、以来源为主补空白；可选余额、持有、进度与历史范围。零值视为空白，数量不相加，卡池进度与历史整组择一，不拼接保底、井或记录。目标身份、双语名称与默认标记保留；旧数据账户尚未填写余额时，不能覆盖目标余额。先预览再确认，来源账户保留，可由用户另行删除。融合与一份撤销备份在同一次写入提交；目标未再次修改前支持撤销上次融合。跨页修改或存储失败均不部分提交。重组持有或进度后移除旧录入同步贡献，下次录入重新建立基准。

设置“录入记录同步至玩家数据”默认关闭，关闭只存账号历史。开启后以同步前玩家进度和已有记录建立基准，默认只重放后续录入结果，不随机抽卡；同步当前池规则进度和明确且能唯一识别的物品数量。未指定名称及自动随机贴图不计入真实持有，不结算货币或返还，也不自动生成井物品或赠送抽。重复保存、编辑和删除同步段均通过重算及持有贡献差额处理。关闭同步保存会结束该同步段；再次开启以当前玩家数据与现有历史重新建立基准。修改同步基准之前的历史不能安全反推玩家起点，须关闭同步后保存。手动编辑玩家进度后重新建立基准，避免覆盖玩家输入；跨页冲突或存储失败不部分提交。

模拟器进入优先级：显式指定玩家数据时应用所选数据；通常先恢复已保留的完整记录，再尝试明确保存的初始设置，最后才显示玩家数据选择。已有玩家账号不会阻挡“记住并自动应用初始设置”；临时使用的数据不参与下次自动恢复。记录损坏时保留原存档并交由用户选择，避免静默覆盖。

模拟器数据选择弹窗用“本次启用货币系统”开关组合空白、所选数据及新建入口，不改设置页偏好。关闭时，新建只填写按卡池配置启用的垫抽、保底、井等规则进度。新建编辑返回上一步会回到数据选择，放弃未保存内容和应用数据均需确认；浏览器离开也保护未保存草稿。新建支持“仅本次使用”和“保存到玩家数据并使用”：前者使用页面内存账号／恢复基准，后续扣款、持有及结果进度也不写入本机存档，离开后失效，即使开启保留进度或浏览器返回也不会恢复；后者将初始快照保存为玩家数据后应用，模拟抽卡不回写快照。

多账号支持勾选“默认账户”，随“保存数据”一起提交；每游戏最多一个，保存新的默认账户会同时取消其他账户的默认状态。模拟器优先选中默认账户，单一模式也优先显示默认账户。没有指定或删除默认账户后，再次进入上述页面会自动创建默认账号；其他已有账号保留。此偏好不会自动应用账户，也不会覆盖已保留的模拟进度。

玩家账号名称在卡片顶部直接编辑，使用 name／en 分别保存中英文，另一语言入口跟随“双语编辑”偏好；正文不再重复名称框。修改仅在保存数据后落盘，还原未保存修改会同时恢复两个语言字段。模拟器的账号选择名称跟随界面语言显示，缺失时回退另一语言。

玩家数据页面的管理模式在设置页选择，默认“单一数据”：直接在页面展开全部编辑内容，隐藏新建及删除，优先显示默认账号，未指定时显示第一份账号数据；其他账号保留。“多账号数据”保留新建及删除，使用可展开／收起的账号卡片在页面内编辑。切换模式不删除数据；保存一张卡片不重建其他卡片，避免丢失其草稿。玩家页不再提供进入卡池、进入模拟器或使用数据的跳转入口。

“玩家数据”页管理用户自己的游戏账号，不需要也不会写入 db_*.js。每份数据在全游戏共用一份余额、票券及角色／物品持有，按分类和物品身份去重；各卡池的垫抽、井、救援等规则进度放入独立 pools 映射。表单从卡池规则配置读取字段，未配置或未启用的规则不显示。旧版单池存档兼容读取为对应卡池进度，原余额与持有保留；保存时升级版本。模拟器只按当前池读取对应进度；货币模式下应用账号数据会同时恢复共享资源和所有已配置卡池的进度。保存玩家数据不会改写实时模拟账户或官方规则，模拟抽卡也不会改写这份初始玩家数据。

核对日期：2026-10-19。对应 `db_zzz.js`、`db_ark.js`、`db_end.js` 中 SETUP_RULES 与 POOL_RULES 之间的 CURRENCY_RULES。游戏内容名称使用 `name` / `en`，跟随现有游戏内容语言设置。

这些规则已接入模拟器的可选货币模式，可在设置页或模拟器快捷弹窗开启，默认关闭。余额、持有件数、领取/兑换额度及各池抽卡进度按游戏保存在本机；结果画面是否恢复由“保留模拟器记录与全部进度”控制。每日与每月额度手动重置，不模拟日期推进。月重置同时清除前置完成确认，余额与持有件数保留。

模拟起点设置可单独开启，默认关闭。起点表单每次从零创建，不回填历史模拟账户的余额、持有及抽卡进度；开启自动填溢出时，仅将当前池低星候选填至各大类满阶件数。选择继续当前进度不会修改账户，明确应用起点后才写入。无论是否开启货币模式，均可填写初始累计抽数、当前垫抽、保底歪数、救援连续歪数及已启用规则的进度；开启货币模式后额外设置资源余额和物品持有。历史井／赠送阈值按已领取处理，未执行的赠送抽需单独填写。应用起点不生成历史抽卡结果，也不发放历史返还。恢复起点清空结果，并恢复当前池进度及同游戏共享的余额、持有和领取／兑换额度；其他池的抽卡进度保留。开启新一期仍按卡池的继承矩阵处理，不覆盖保存的起点。“记住并自动应用初始设置”默认开启、仅在起点设置开启且未开启保留全部进度时显示。先明确应用一次起点，之后每次进入同游戏、同卡池、同模式都会恢复保存的起点并跳过弹窗；普通模式与货币模式分开保存，未保存或无法读取时仍打开从零填写的弹窗。自动捕获的旧恢复基准不视作用户明确保存的起点。

“保留模拟器记录与全部进度”默认关闭。开启后按游戏、卡池和普通／货币模式保存结构化结果、候选选择及引擎进度；货币模式同时沿用共享资源账户并保存支付选项。再次进入时优先恢复离开前的进度，隐藏初始设置记忆开关，但保留明确保存的起点供手动重置使用。没有记录时仍可自动应用已保存的起点。恢复结果只重新绘制，不重新抽卡、扣款或发放返还。货币扣款、持有、进度与记录在同一次账户写入中提交，存储失败不提交部分结果；无法读取的记录保留原存档，提示重新设置起点。

满阶件数含首次；多个副产物规则命中时叠加。兑换多选表示择一领取。月限购按目标资源分别计数；阶梯则按顺序整档兑换，每月重置（一次性阶梯不重置）。阶梯的获得资源仅填各档 `stages[].toIds`，不再填写上层 `toIds`；旧配置的继承目标会迁入各档。引擎赠送抽不扣资源，也可产生副产物；额外井奖励只计入持有件数。

四游戏均提供“自定义获取＋货币名”条目。方舟与绝区零由原日常条目改名，保留每日100合成玉/60菲林；崩铁与终末地补充不限次数、每次1的自定义初始值，不代表实际每日任务奖励。

共享兑换组／层级使用 economy.unlockGroups，每组保存 id、name/en、period（monthly/once）、prerequisite/prerequisiteEn（仅展示）、requirements 和 costs。兑换通过 unlockGroupId 加入，组内多个项目共用一次解锁，兑换费用另付。前置多选且全部满足，支持指定目标、次数或兑换至上限；阶梯按已完成档数，月限购按实际兑换目标分别计数。costs 为额外解锁费用，可配置多种资源，同资源费用合并检查，前置或余额不足不扣款。扣款及解锁在同一账户事务中保存，重复解锁不扣费。默认数字由配置者直接填写，不执行文本算式。
模拟器显示每项前置完成进度、所需余额及解锁状态，不满足时禁用解锁和组内兑换。月重置恢复月度兑换额度和月度前置计数，并锁定 monthly 组；once 组永久保留解锁，永久条件使用累计兑换次数。每日重置不清除兑换解锁。规则保存校验无效资源、已删除引用、自引用、循环依赖、不可达次数及无限兑换的“兑换至上限”；被组引用的兑换、资源或组须先解除引用才能删除。旧式 hasPrerequisite + prerequisite 文本确认保持兼容，加入共享组后由组统一管理，不重复要求手动确认。
方舟第二层示例：第一层合成玉40×6＋寻访票240×2＝720，完成两项后额外扣770，总计1490。第三层沿用现有10500第二层消费条件，先兑换第二层寻访票450×2＝900，再扣9600。上述额外消耗不产生抽卡资源。开发演示 output/exchange-groups-preview.html 使用独立演示账户及同一套正式组件，不修改玩家账号。

玩家数据页在初始货币与票券之后、各卡池进度之前提供“资源兑换”。四个主要分区均可折叠；兑换区按普通兑换、月限购、月阶梯、一次性及共享兑换组折叠。ui/resource_exchanges.js 为模拟器与玩家表单共用的兑换界面，使用 SimulatorEconomy 的同一套扣费、限购、阶梯、前置与共享解锁结算。玩家表单只修改内存草稿，成功后回填余额并标记未保存；不写实时模拟账户，保存数据时与账号原子提交，还原会恢复保存的余额与进度。月度兑换重置需确认，同样仅修改草稿，保留余额与永久解锁。
玩家行的可选 economyProgress 字段保存 exchanges 和 prerequisites。旧行缺省等同零进度。应用玩家数据到货币模拟时复制此进度而不是清零，起点快照与恢复也包含它；模拟操作不回写玩家行。普通模式不应用兑换状态。融合的“卡池、兑换进度与记录”范围将整组选取兑换状态，不将兑换次数相加，并在预览中显示变化，撤回使用原始快照。

模拟器资源管理使用 SimulatorEconomy.resourceScope(poolId)，从当前卡池全部适用的支付资源反向查找兑换上游，同时筛选余额、领取来源、兑换项目、共享组和每档可选目标。同一兑换项目的其他备选目标不会因共用成本资源而被带入；必经的前序阶梯、共享组前置兑换与额外解锁消耗则保留。没有适用支付配置时不回退为全游戏展示。共享兑换界面执行前再次验证目标属于当前范围，防止沿用过期目标；不传 poolId 的玩家数据表单保留整个账号的兑换规则和目标。

录入同步先检查本次重放报告，存在异常记录或换期前遗留违规时，整批不更新玩家进度与明确持有；仅原子保存录入记录、原同步基准及 dashboardRecords[pool].syncBlocked（invalid_history）。玩家数据页在对应账号标题处用红色边框和提示列出受影响卡池，跨页保存时即时刷新且不覆盖表单草稿。关闭同步或手动保存玩家表单不消除该标记；修正录入并成功同步后，仅清除该卡池标记。保留原已同步贡献，修复后继续按贡献差额更新，避免重复增加或错误扣回。

账户用途 purpose 为 record（结果记录用）或 simulation（抽卡模拟用），缺省旧账户按 record 处理，不改写已有数据。新建时选择，保存后禁止更改用途。结果账户在玩家数据页仅锁定各卡池进度与初始角色／物品持有；余额、资源兑换和名称仍可编辑保存，默认勾选仍可立即保存。保存货币修改时保留原有进度、持有及初始快照；自动建立的全空白默认账户允许完成首次配置。模拟账户持续可编辑，结果看板只列出结果账户；两类均可复制到模拟器，模拟不回写原账号。融合仅允许可编辑账号作为目标，结果账号可作为来源。
结果初始进度 recordInitial 与当前 pools 分开保存。新建结果账户时快照起点，旧账户首次录入时仅为该池固定基准：已有历史默认从零展示以免重复计算，无历史则使用原玩家进度；已同步且空历史基准沿用其 baseState。结果页按当前启用规则展示起点，从起点重放记录得到当前垫抽，初始累计抽数用于录入编号；总抽数、出金率和平均出金只统计明确录入记录，不制造历史抽数。

历史出金汇总 recordStats 按卡池保存 {gold,up}，独立于物品持有和引擎进度；结果账号的未知汇总可补填一次，保存后锁定；模拟账号可持续修改。旧起点累计抽数等于当前垫抽、goldCount 为零且无保底歪数／救援／早金等出金迹象时，可确定为 0 金 0 UP：读取时计算兼容值，不静默写盘，正常保存时写入。不能确定的旧数据不猜测。填写时需要两项均为非负整数、up ≤ gold ≤ 初始累计抽数。无论是否填写汇总，初始累计抽数始终进入总抽数。未填写历史出金时，出金率、不歪率、平均出金仅按逐抽记录计算，并标明范围；填写（包括明确的 0）后合并历史出金、UP 和歪数。星级分布仍只统计逐抽记录，汇总不生成历史记录或发放资源。融合进度时快照和汇总随同一卡池整体转移。

同步修正：有 recordInitial 且非旧迁移账户时，从固定起点重放全部记录来计算进度；首次同步是否包含已有记录只控制物品贡献，避免首个十抽被排除。保存一次合法记录即可修复旧的缺十抽进度。旧迁移账户不推测基准；检测到手动改写同步状态后保留手动基准，非法记录仍整批阻止同步。

初始历史汇总额外校验：普通计保底抽数中，累计减当前垫抽为已结束的出金段；零金要求该差为零，每段至少一抽且不超过当前启用的硬保底。UP／歪总数还须容纳当前歪数，经典大保底校验各 UP 之间可容纳的歪数及末尾歪数；救援当前连歪不得超过历史歪数。存在不计保底赠送抽时，不用总抽数强推普通抽数边界。初始汇总与后续录入分别计数。错误旧汇总仍可读取、显示错误、开放修正，修正合法后重新锁定；错误汇总不参与出金相关统计。

当前进度独立校验 progressErrors：不依赖历史汇总，检查累计数 ≥ 各垫抽、垫抽低于各自硬保底、当前歪数／救援连歪／已用早金特权须有足够历史抽数且不超规则上限，以及井／赠送进度不得超过累计数。表单实时显示当前进度错误，构建起点和保存已改变的玩家进度时再次检查。已同步的账户上方显示“当前累计抽数”，下方历史汇总仍单独对应录入前起点，两个区域分别报错。
